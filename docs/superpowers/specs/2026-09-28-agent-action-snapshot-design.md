# Agent Action Snapshot Design

## Goal

Add a structured, single-call browser observation for autonomous assistants, with optional stale-observation protection on click and fill operations. Existing browser tools keep their current behavior unless callers opt in by supplying a snapshot ID.

## Interface

Add `chrome_get_action_snapshot` with the same target selection convention as other page tools (`tabId` and `windowId`). It returns JSON text containing page identity, bounded visible text, a shared `snapshotId`, and visible actionable controls. Each control includes its frame ID, existing element ref, accessible role and name, current value/state, and supported operations (`click`, `type_text`, or `select`). Password and file inputs are excluded. Snapshot output is capped at 150 controls across the page and follows the existing 24 KB default output budget.

`chrome_click_element` and `chrome_fill_or_select` gain an optional `snapshotId`. When present, it is forwarded to the target frame and checked at the point of mutation. When absent, current behavior is unchanged. A snapshot is valid for 30 seconds; each frame retains at most five snapshots. Snapshot IDs are generated by the extension background, shared across reachable frames, and stored with per-frame guards.

## Freshness and execution

Before a snapshot-scoped click or fill, require the ref to belong to that snapshot and recheck that its node is connected, visible, enabled, and still has the same role, accessible name, value/state, and nearby semantic context. A missing, expired, or changed snapshot returns a stale-observation error before input. Existing click geometry, scrolling, and hit testing remain the final execution checks. Unrelated page mutations do not invalidate a target when its observed identity and local context remain the same.

After a snapshot-scoped fill of a combobox, wait with a MutationObserver for a visible option in its `aria-controls`/`aria-owns` targets, for at most 200 ms. This wait is only for opted-in snapshot calls. The following action snapshot reads the resulting suggestions. Other fills and all legacy calls have no added wait.

## Validation

Add offline extension tests using the existing injected-helper DOM fixtures for snapshot shape and limits, allowed operations, sensitive-field exclusion, matching and stale snapshot guards, replaced/hidden/disabled controls, cross-frame IDs, overlay checks, and combobox option arrival/timeout. Add a deterministic local benchmark fixture that compares the legacy read-plus-element-discovery path with one action-snapshot read, records call count and elapsed time, and independently verifies the resulting page state. Update English and Chinese tool schemas and API reference docs.

## Compatibility

This is an additive MCP tool and optional input property. Existing clients and tool flows do not need to send `snapshotId`; selectors, markers, coordinates, refs, and frame targeting retain their established semantics.
